Bidirectional LSTM on MNIST: reading an image like a sentence, and what that does and doesn't buy¶

The question: an LSTM is built to read a sequence, one step at a time, remembering what it has seen. A digit image is not obviously a sequence, but we can read it one row at a time, from top to bottom. A bidirectional LSTM also reads it from bottom to top and combines the two readings. It scores about 99% on MNIST, but the headline hides better questions. Is the legacy code reading the model's output correctly, does reading both ways actually help, does the model really use the order of the rows, and how much of the image does it need to see?

1. 💡 The simple analogy¶

Imagine you have to name a handwritten digit that is being slowly revealed through a slot, one thin strip at a time, from the top down.

  • A unidirectional LSTM is a reader who watches the strips go by, keeping a running mental note ("so far I've seen a curve, then a loop..."). At the end, they say the digit.
  • A bidirectional LSTM hires a second reader who looks at the strips in reverse, from the bottom up, with their own running note. The two readers compare notes before answering.
  • The legacy code made a subtle mistake: it asked the bottom-up reader for their note right after they had read only the very first strip they saw, the bottom one, which is blank. That reader's note was not much use.
  • A sentence-shuffling test asks: does the reader rely on the order of the strips? If you shuffle the strips and the answer falls apart, they do.

3. Audit the data first¶

What: load MNIST (60,000 training and 10,000 test images of handwritten digits, 28 x 28 pixels) and treat each image as a sequence of 28 rows, each with 28 pixels. Why: before training we should know the shapes, the baseline score of a clueless guess, and where the ink sits, since the top and bottom of the sequence are where the "reader" starts.

Problems in the legacy scripts this replaces: the model's output was read from out[:, -1, :], which for the backward direction is the state after seeing only the last row (see H1). The scripts also reported a single run (99.53% train, 98.94% test) with no seeds, no baseline and no uncertainty, and tested on a shuffled test loader.

def load_mnist() -> tuple[torch.Tensor, torch.Tensor, torch.Tensor, torch.Tensor]:
    """Loads MNIST as float images in [0, 1] with shape (N, 28, 28): 28 rows of 28 pixels.

    Returns:
        Training images and labels, then test images and labels, all on the compute device.

    Raises:
        ValueError: If the dataset does not have the expected shape.
    """
    with contextlib.redirect_stderr(io.StringIO()):  # hide the download progress bars
        train = datasets.MNIST(DATA_DIR, train=True, download=True)
        test = datasets.MNIST(DATA_DIR, train=False, download=True)
    if tuple(train.data.shape) != (60_000, 28, 28) or tuple(test.data.shape) != (10_000, 28, 28):

    return (
        train.data.float().div(255).to(DEVICE),
        train.targets.to(DEVICE),
        test.data.float().div(255).to(DEVICE),
        test.targets.to(DEVICE),
    )

4. Hypotheses and why we chose each test¶

# Question H₀ (nothing interesting) Hₐ Test
H1 Does reading each direction's true final state beat the legacy readout? Same accuracy Proper readout is higher 10 paired seeds, Wilcoxon, bootstrap CI; exact McNemar on shared test images
H2 Does reading both ways beat reading one way? Same accuracy Bidirectional is higher 5 seeds each, Mann-Whitney U, Cliff's δ; unidirectional models at the same width and at the same number of weights
H3 Does the model rely on the order of the rows? Shuffling rows at test time changes nothing Accuracy falls Test on shuffled and reversed rows; retrain on shuffled rows; Mann-Whitney
H4 How much of the image does each model need to see? Accuracy depends only on the number of rows seen Differs by model Accuracy as the visible rows are cut from 28 down to 4, 5 seeds

Why these tests? Accuracy over seeds is not normally distributed with so few runs, so rank-based tests (Wilcoxon, Mann-Whitney) are the safe choice. McNemar's test is exact for comparing two models on the same test images (only the images where they disagree carry information). The parameter-matched comparison in H2 is essential: a bidirectional model has about 2.6 times the weights of a one-way model of the same width, so any gain could just be extra capacity.

5. The model¶

What: a 2-layer LSTM with 128 hidden units per direction that reads the 28 rows in order and then a linear layer that turns a summary of the reading into ten digit scores. We trained with Adam (learning rate 0.001, batches of 128) for 6 epochs and report the final-epoch test accuracy: the test set is never used to choose anything.

The key choice, the "readout": what do we hand to the final linear layer?

  • Legacy: outputs[:, -1, :], the output at the last time step, for both directions. For the forward direction this is correct: it has read every row. For the backward direction, however, the last time step is the first thing it reads, so it has seen only row 27.
  • Proper: each direction's true final state (h_n): the forward direction after row 27, the backward direction after row 0.

Everything else (weights, data, seeds) is identical, so any difference comes from the readout alone.

class RowLSTM(nn.Module):
    """Reads an image one row at a time with an LSTM and classifies the digit.

    Args:
        bidirectional: If true, a second LSTM reads the rows bottom-to-top.
        readout: ``"legacy"`` takes the output at the last row for both directions (what the
            original script did); ``"final"`` takes each direction's true final state.
        hidden: Hidden size of each direction.
    """

    def __init__(self, bidirectional: bool, readout: str, hidden: int = HIDDEN) -> None:
        super().__init__()
        if readout not in {"legacy", "final"}:
            raise ValueError("readout must be 'legacy' or 'final'")
        self.bidirectional = bidirectional
        self.readout = readout
        self.lstm = nn.LSTM(
            x_train.shape[2], hidden, LAYERS, batch_first=True, bidirectional=bidirectional
        )
        self.head = nn.Linear(hidden * (2 if bidirectional else 1), 10)

    def forward(self, rows: torch.Tensor) -> torch.Tensor:
        """Class scores for a batch of images of shape (batch, rows, pixels)."""
        outputs, (h_n, _) = self.lstm(rows)
        if self.readout == "legacy":
            summary = outputs[:, -1, :]
        elif self.bidirectional:
            summary = torch.cat([h_n[-2], h_n[-1]], dim=1)  # last layer: forward, then backward
        else:
            summary = h_n[-1]
        return self.head(summary)


def count_weights(model: nn.Module) -> int:
    """Number of trainable weights."""
    return sum(p.numel() for p in model.parameters())


def train_model(
    bidirectional: bool,
    readout: str,
    seed: int,
    hidden: int = HIDDEN,
    row_order: torch.Tensor | None = None,
) -> RowLSTM:
    """Trains a row-reading LSTM for a fixed number of epochs (no peeking at the test set).

    Args:
        bidirectional: Whether to read both ways.
        readout: ``"legacy"`` or ``"final"``, see ``RowLSTM``.
        seed: Seed for weights and batch order.
        hidden: Hidden size per direction.
        row_order: Optional fixed permutation of the 28 rows applied to every image.

    Returns:
        The trained model in evaluation mode.
    """
    torch.manual_seed(seed)
    model = RowLSTM(bidirectional, readout, hidden).to(DEVICE)
    optimizer = torch.optim.Adam(model.parameters(), lr=LEARNING_RATE)
    images = x_train if row_order is None else x_train[:, row_order]
    for _ in range(EPOCHS):
        model.train()
        order = torch.randperm(len(images), device=DEVICE)
        for start in range(0, len(images), BATCH):
            pick = order[start : start + BATCH]
            loss = nn.functional.cross_entropy(model(images[pick]), y_train[pick])
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
    return model.eval()


def predict(model: nn.Module, images: torch.Tensor) -> torch.Tensor:
    """Predicted digits for a batch of images.

    Args:
        model: A trained classifier.
        images: Tensor of shape (n, rows, pixels); ``rows`` may be fewer than 28.

    Returns:
        Predicted labels, shape (n,).
    """
    with torch.no_grad():
        return torch.cat(
            [model(images[i : i + 2000]).argmax(1) for i in range(0, len(images), 2000)]
        )


def accuracy(model: nn.Module, images: torch.Tensor = x_test) -> float:
    """Test accuracy of a model."""
    return float((predict(model, images) == y_test).float().mean())

6. H1: is the legacy way of reading the answer correct?¶

What: train the bidirectional model 10 times for each readout, using the same seed for the legacy and the proper run so that both start from the same random weights and see the same batches (a paired design). We compare the test accuracies with a Wilcoxon signed-rank test and a bootstrap CI on the mean difference. For seed 0 we also run an exact McNemar test on the 10,000 shared test images.

Why we might not expect a big gap: with two layers, the second layer's forward LSTM reads the first layer's outputs, and those already include a bottom-up reading. So the legacy model can still get the full image through the second layer. The proper readout adds the backward direction's full final summary on top.

  • So the legacy code's reading was a genuine flaw but a mild one: the extra layer rescued most of the information. Without a second layer it would have been far worse; we did not test that here.

7. H2: does reading both ways help?¶

What: compare the proper bidirectional model with unidirectional models, which read the rows only top-to-bottom, trained 5 times each:

  1. A unidirectional model with the same width (128 hidden units): fewer weights (214,282).
  2. A unidirectional model with the same number of weights (210 hidden units, 558,190 weights): the fair comparison.
  3. For reference, the legacy bidirectional readout.

We compare with Mann-Whitney U tests and Cliff's δ as the effect size (+1 means the first group always scores higher).

def hidden_matching(target_weights: int) -> int:
    """Hidden size for a one-direction LSTM whose weight count is closest to ``target_weights``.

    Args:
        target_weights: The weight count to match.

    Returns:
        The hidden size.
    """
    sizes = range(64, 400)
    return min(sizes, key=lambda h: abs(count_weights(RowLSTM(False, "final", h)) - target_weights))

How to read this:

  • Mean test accuracy (5 seeds): unidirectional with 128 hidden units 98.38%; unidirectional with 210 hidden units (matched weights) 98.65%; bidirectional (proper) 98.59%; bidirectional (legacy) 98.41%.
  • Against the same width, bidirectional is +0.21 points higher (Mann-Whitney p = 0.116, Cliff's δ = 0.64): a sizeable effect, but with only 5 seeds not significant.

8. H3: does it really use the order of the rows?¶

What: four tests on the proper bidirectional model (5 seeds each):

  1. Normal order (the baseline).
  2. Trained on normal images, tested with the 28 rows shuffled (one fixed random shuffle). If the model relies on row order, this should wreck it.
  3. Trained normally, tested upside-down (rows in reverse order).
  4. Trained and tested with the same shuffled rows. A fixed shuffle is just a relabelling of the rows, so a flexible model can still learn it, but the "natural" sequence (a stroke continuing from one row to the next) is gone.

Why: it separates "the model learned the spatial layout it was trained on" from "the model can read any ordering".

Normal order vs trained on shuffled rows: +1.51 points, Mann-Whitney p = 0.008

How to read this:

  • The trained model depends heavily on the row order: tested on shuffled rows it falls from 98.59% to 21.17% (range 20.07% to 23.56%); tested upside-down it reaches only 38.56% (37.06% to 41.35%). We reject H₀.
  • But the order itself is not special: trained and tested on the same shuffled rows, it still reaches 97.08% (96.93% to 97.17%). It simply uses whatever fixed order it was trained on.
  • The natural order helps a little: normal order beats the shuffled-and-trained version by 1.51 points (Mann-Whitney p = 0.008, the smallest value 5 against 5 seeds can give). The LSTM gets a modest bonus from strokes that flow from row to row; it can still learn a scrambled order, because the sequence is just 28 numbers it can memorise a position for.
  • This also warns against reading too much into "sequence models": on MNIST the LSTM is not discovering time, it is learning a layout.

9. H4: how much of the image does it need?¶

What: the three models trained on all 28 rows (unidirectional, bidirectional proper, bidirectional legacy; 5 seeds each) are tested when only the first k rows are fed in (k = 4, 8, ... 28) and nothing else. Why: a sequence model can in principle answer early, and the bidirectional reader should be better at it because its backward half reads the visible rows from their last row upwards. Caveat: the models were trained on full images, so cutting rows is also a shift in the data.

11. 🎯 Takeaways¶

  1. The legacy readout was a real but mild flaw: taking the output at the last step gives the backward direction only the last row. The proper readout gains 0.23 points (CI +0.09 to +0.38; 7 of 10 seeds) on complete images.
  2. The flaw bites hard when the image is cut short: at 16 visible rows the proper bidirectional model scores 55.8%, the legacy readout 14.8% (unidirectional 19.1%).
  3. Bidirectional is not magic: a unidirectional model with the same number of weights scores 98.65% against 98.59% for the bidirectional one (p = 0.31). On MNIST it is capacity, not reading direction, that matters.
  4. The order of the rows is what the model learned, but any fixed order works: shuffled at test time it falls to 21.2%; trained on a shuffled order it reaches 97.1%.
  5. Always report runs, not a run: the legacy "98.94%" is one number; across seeds a single configuration spans about 0.3 to 0.5 points, as large as most of the differences in this notebook.

12. ⚠️ Limitations¶

  • Few seeds (10 for H1, 5 elsewhere), so several p-values are at or near their minimum possible value and some effects (H2) are too uncertain to call.
  • A short, fixed training budget (6 epochs): longer training would change the absolute numbers and may change the gaps.
  • One architecture family and one dataset. The conclusions are about row-wise LSTMs on MNIST; on real sequences, such as text or sensor data, a backward reading often matters far more.
  • The truncation test shifts the data as well as removing information, because the models were not trained on shorter inputs.
  • We did not test a one-layer legacy readout, where the flaw would probably bite much harder.
  • The legacy scripts were not run as written: we reproduced their readout inside our own training loop, with our own epochs and batch size, so the legacy 98.94% should not be compared with our numbers directly.
